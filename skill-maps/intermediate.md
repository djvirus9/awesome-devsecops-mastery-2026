# Intermediate skill map

Prerequisite: [beginner evidence](beginner.md). Follow phase order: [Lab 06](../labs/lab-06-dast-api-testing/README.md) → [Lab 04](../labs/lab-04-k8s-admission-policies/README.md) → [Lab 05](../labs/lab-05-runtime-detection/README.md). These correspond to Phases 4, 5, and 6. Allow 4–8 weeks part time.

## Assessable outcomes

- Map every sample route and owner to expected success/denial tests; explain coverage gaps.
- Show allowed and denied policy fixtures and distinguish local rule evaluation from cluster admission.
- Explain secret delivery, runtime identity, network boundaries, and rollback requirements for a proposed deployment.
- Produce the expected synthetic detection and telemetry-gap alerts; show that routine events remain quiet.
- Record an exception with narrow scope, approver, expiry, compensating control, and closure criterion.

Deliver a promotion/rollback design referencing one application artifact and retained evidence. If a practice cluster is available, add admission and rollback results; otherwise label them pending. Do not claim deployment enforcement from offline policy tests alone.

Review the [role handoffs](../docs/learning-paths.md) and continue to [advanced](advanced.md).
